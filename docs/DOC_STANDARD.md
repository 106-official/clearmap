# ClearMap · 项目文档维护规范（DOC STANDARD）

> 本文件是**后续任何人 / 任何一次迭代完善项目文档时都必须遵守的标准**。
> 改动代码的同时，请在本次 PR / 交付说明里标注「是否触及文档」；凡涉及下述目录的变更，一律按本标准同步更新后再交付。
>
> 目标：让每份文档①可复审——能回溯到真实代码；②可执行——照着做就能复现；③唯一、不重复——同一信息只在一处维护。

## 1. 通用写作规范

### 1.1 语言
- 一律用**简体中文**；专有名词、代码标识符、命令保留原文（如 `Flask`、`app.py`、`localStorage`）。
- 语气对象：`README / API / LOCAL_SERVER` 尽量面向**能读懂代码的人但要能照做**，避免过于口语或过于抽象。

### 1.2 结构与层级
- 顶层用 `#`，一级分节用 `##`，小节用 `###`；层级最多 3 层，避免过深。
- 每份文档开头要有：一个 `>` 引言（一句话说明这份文档干嘛、给谁用）+ 目录（锚点列表）。
- 长段落拆分：一个自然段只说一个动作 / 一个事实。

### 1.3 可复现性（最关键）
- 所有**命令**用代码块 + 语言标注（`bash` / `powershell` / `python` / `json`），并注明**在哪个目录、哪个系统**执行。
- 所有**路径**用反引号包裹，并区分相对根目录还是相对某目录。
- 涉及**端口 / 地址 / 账号**的示例，统一用 `127.0.0.1:9100`、`13800138000`、`123456`、`clearmap2026` 这类明确标注的假值，防止误当真实配置。
- 给出预期输出：命令后尽量附一行「成功时会看到…」的样例。

### 1.4 代码引用
- 引用现有代码时用**点击式文件链接** `[文件名](file:///绝对路径)`，并尽量带行号范围（`#L10-20`）。
- **不要**把大段代码复制进文档当「附录」，除非确实需要，否则一律指向原文。

### 1.5 示例数据
- 接口示例的 JSON 必须与 `docs/API.md` 中**该接口真实返回结构逐字段一致**。
- 状态码用标准语义：`200 成功`、`400 参数/业务错误`、`401 未认证`、`404 不存在`、`409 冲突`、`429 限流`，错误消息给中文示例。

## 2. 接口文档 `docs/API.md` 标准

1. **新增接口**时，每个接口按固定五段式书写：
   - `### METHOD /api/path?`（含 query 参数写法，带 `?` 表示无鉴权默认游客、token 走 query）。
   - `请求体`（JSON 代码块，逐字段注释）。
   - `成功响应`（代码块 + 字段说明）。
   - `失败响应`（至少列出最常见的 1–2 个错误码）。
   - `鉴权`（是否为"无需身份"接口，`resolve()` 表现）。
2. **修改响应结构**时，必须同步更新对应响应 JSON 与 `GET /api/me` 聚合接口的字段说明。
3. **删除接口**时，在该节上方标注「已废弃（版本 / 日期）」，说明替代接口，不可直接删节、不留引用的悬空链接。
4. 每次变更后，在 `docs/API.md` 末尾追加一行变更记录：`- [版本/日期] 新增/修改/删除：接口名——一句话说明`。

```markdown
### POST /api/example?p=
新增说明（一句话）。
请求体：
```json
{ "field": "说明" }
```
成功响应 `200`：
```json
{ "ok": true, ... }
```
失败 `400`：`{ "ok": false, "error": "中文错误" }`
```

> 校验清单（每改一个接口逐条勾选）：
> - [ ] 五段式齐全
> - [ ] 请求体字段与代码 `*args` 一致
> - [ ] 响应字段与 `data.py` / `api.py` 实际返回一致
> - [ ] 鉴权标注正确
> - [ ] API.md 末尾变更记录已加

## 3. 部署文档 `docs/LOCAL_SERVER.md` 标准

1. 步骤必须是「Windows 用户能照做」的粒度：安装 → 获取程序 → 启动 → 查地址 → 防火墙 → App 配置 → 验证 → 排错。
2. 出现「内网 IP / 端口映射 / 防火墙」这类概念时，给一句**普通口语解释**，不默认读者懂网络。
3. 每步给出「成功标志」与常见失败现象对照表（FAQ）。
4. 后端启动方式或端口变更时，必须同步本文件与 `启动.bat` / `deploy/start_laptop.bat`。

## 4. README 标准

1. 每次**新增能力**，在「功能特性」补一条，并同步「项目结构」与「快速开始」（若启动方式没变，则只补特性 + 文档角标 `docs/`）。
2. 「技术栈 / 项目结构」与真实代码保持一一对应；增删文件要同步到结构树。
3. 交付 APK 时，在 README 相关段落写明 **版本号、文件路径、签名信息** 的存放处（详见 `mobile/README.md`）。

---

## 5. Changelog / 变更记录（强制）

- 在 `docs/API.md` 维护**接口**变更记录（见第 2 节）。
- 在 `README.md` 顶栏「版本历史」或单独 `CHANGELOG.md`（若已有）维护**功能级**变更记录，格式：
  ```
  ## v-1.22 (YYYY-MM-DD)
  - 新增：地图双指缩放 / 全屏沉浸
  - 新设：底部「发现」栏、随笔发布
  - 修复：红绿点点击无详情
  - 移除：行程半日/全天/慢游按钮
  - 文档：新增 DOC_STANDARD / LOCAL_SERVER
  ```
- 每次交付必须至少推进一次功能级变更记录。
